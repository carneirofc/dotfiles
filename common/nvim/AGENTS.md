# AGENTS.md — common/nvim

## Purpose

- Cross-platform Neovim config. Linux symlinks `~/.config/nvim` here; Windows
  copies it to `%LOCALAPPDATA%\nvim`. Targets Neovim 0.11+ (tested on 0.12).

## Ownership

- Owns every file under `common/nvim/`. Parent rules (CHANGELOG, commits,
  branch + PR) come from the root `AGENTS.md`.

## Local Contracts

- Load order is fixed in `lua/carneirofc/init.lua`: `packer` → `settings` →
  `keymaps` → `plugins` → `lsp` (LSP last, because it depends on plugins).
- Plugin manager is packer (`lua/carneirofc/packer.lua`). Declare each plugin
  once. `plugin/packer_compiled.lua` is generated by `:PackerCompile` and
  git-ignored; never commit it (it hardcodes absolute plugin paths).
- One `lua/carneirofc/plugins/setup-<plugin>.lua` per plugin, each exporting
  `M.setup()`, registered in `plugins/init.lua`. Delete the file when the
  plugin is dropped; no dead setup files.
- LSP (`lua/carneirofc/lsp/init.lua`):
  - Configure servers with `vim.lsp.config(name, overrides)` and enable with
    `vim.lsp.enable`. Never call `require('lspconfig').<server>.setup` (the
    deprecated framework; removed in nvim-lspconfig v3).
  - Server definitions come from nvim-lspconfig's `lsp/` directory.
  - Mason-managed servers go in `mason_servers` (installed + enabled by
    `mason-lspconfig`, `ensure_installed` + `automatic_enable`). System
    servers go in `system_servers` and are enabled only when their binary is
    executable. none-ls tools go in `mason_tools`.
  - Buffer keymaps live in the single `LspAttach` autocmd.
  - `lazydev.nvim` provides lua_ls workspace settings; do not hand-roll
    `Lua.workspace.library`.
- Keymaps: `<C-h/j/k/l>` are window navigation (global, `keymaps.lua`) and
  must not be rebound by plugins or LSP; `<leader>e` is the diagnostics float;
  signature help is Neovim's built-in insert-mode `<C-s>`. Telescope uses
  `<leader>f*`, LSP uses `<leader>{rn,ca,ds,ws,wa,wr,wl}`, `g{d,r,I,D}`, `K`.
- Remote-plugin providers (python/perl/ruby/node) are disabled in
  `settings.lua`; no plugin here may depend on them.
- Status line is galaxyline with local providers built on
  `vim.diagnostic.count` / `vim.lsp.get_clients`; do not use galaxyline's
  built-in `Diagnostic*` / `GetLspClient` providers (deprecated LSP APIs).
- Formatting style: 4-space indent, single quotes preferred (`stylua.toml`).

## Work Guidance

- When adding a server: Mason-installable → append to `mason_servers`;
  system package → append to `system_servers` and document the package in
  the README Neovim section. Per-server overrides go through
  `vim.lsp.config`.
- When adding a none-ls tool: add the builtin to `setup_null_ls` and the
  mason package name to `mason_tools`.
- Keep the README Neovim section's dependency list in sync with the lists in
  `lsp/init.lua`.

## Verification

- `nvim --headless -c 'messages' -c 'qa!'` must print nothing (any output is
  a startup error or deprecation trace).
- `nvim --headless -c 'checkhealth vim.deprecated vim.provider null-ls vim.lsp' -c 'w! /tmp/h.txt' -c 'qa!'`
  then grep `/tmp/h.txt` for `ERROR`: none may come from this config.
  Acceptable warnings: missing optional mason languages, missing clipboard
  tool on a bare machine.
- `nvim common/nvim/init.lua` → `:LspInfo` lists `lua_ls` attached.
- `mason-lspconfig` skips `ensure_installed` under `--headless`; to force it
  in a script call `require("mason-lspconfig.features.ensure_installed")()`
  after a registry refresh.

## Child Index

- None. `scripts/.clang-format` is a shared clang-format style; `.luarc.json`
  and `stylua.toml` are tooling config.
